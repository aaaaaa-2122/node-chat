## 一、项目是什么

一个**四端即时通信系统**（TCP/NDJSON 协议），服务器部署在腾讯云广州轻量服务器：

| 端 | 技术栈 | 说明 |
| --- | --- | --- |
| 服务端 `server/` | Node.js | NDJSON over TCP，监听 9099，首登自动注册，支持可选应用层帧加密 |
| 桌面端 `desktop/` | C# WinForms / .NET Framework 4.8 | 全 GDI+ 自绘，单 exe 约 100KB |
| 安卓端 `android/` | Java + WebView，无 Gradle | 手写 build.sh，apk 约 77KB，内置演示服务端 |
| 命令行 `cli/` | C# net48 控制台 | 单文件 30KB 零依赖，可脚本化 `--json` 输出 |
| 网页端 `web/` | 原生 JS + 零依赖 WebSocket 网关 | 登录/群聊/私聊/图片/头像/未读/移动端适配 |

辅助件：
- `agentbus/` —— agent 信箱工具（守护 + 唤醒 + CLI），让 AI agent 能稳定收消息
- `release/` —— 打包发布脚本

**线上可用入口：`http://203.0.113.10/`**（网页端）
**服务端 TCP：`203.0.113.10:9099`**

## 三、架构：网页端为什么需要网关

浏览器开不了裸 TCP，所以网页端中间加了一层**不解析聊天协议**的网关：

```
浏览器 ──WebSocket──> gateway.js (:80) ──TCP/NDJSON──> server.js (:9099)
                        ↑ 同时托管静态页面
```

网关只负责「搬 JSON 行」，不懂聊天协议——所以协议加字段不用改网关。

**在线现状：`--port 80`，无 TLS。** 网关支持可选的 `--tls-cert/--tls-key`、`--redirect-port`、`--acme-root`、`--tls-host`，但这些是为自有域名准备的，当前域名方案已废弃（见下方「域名结论」），故保持明文。

| --- | --- |

| 服务端数据 | `/var/lib/node-chat/`（rooms.json / users.json / dms.json / identity.json） |
| 服务端 unit | `/etc/systemd/system/node-chat.service`（9099） |
| 网页端代码 | `/opt/node-chat-web/src` + `public` |
| 网页端 unit | `/etc/systemd/system/node-chat-web.service`（80，`AmbientCapabilities=CAP_NET_BIND_SERVICE` 非 root 听特权端口） |
| 运行用户 | `nodechat`（无登录 shell） |
| SSH | `ubuntu`@203.0.113.10（sudo 免密），密钥见下方 |
| 证书备份 | `/opt/node-chat-web/certs.disabled-20261121/`（已停用，5KB） |

**数据文件字段速查**（改数据要停服务先备份）：
- `rooms.json`：`dict`，房间键是名字，消息字段是 **`history`**（不是 messages），消息 `{id,room,from,text,ts,image}`
- `users.json`：`dict`，key 是用户名
- `dms.json`：`dict`，键是 `"from\x00to"`
- `identity.json`：服务端身份，**换机/删此文件 = 指纹变化，客户端需 `--pin-reset`**

## 八、踩坑经验（复用价值最高）

### 服务器 / 部署
1. **`curl | sh` 安装器返回 0 但文件可能没装上** —— 必须验证文件真的存在，不能只看退出码。
2. **CRLF 会搞挂远端 bash**（`pipefail: invalid option name`）—— 脚本用 LF，push.sh 打包前 `sed -i 's/\r$//'`。
3. **Git Bash 的 `mktemp -t` 返回 `C:/...`**，tar/scp 会当成「主机:路径」—— 统一用相对路径。
4. **后台进程必须用受管的后台任务**，`(cmd &)` 在命令结束时会被回收（ECONNREFUSED）。
5. **系统防火墙 ≠ 云厂商安全组**：脚本只放本机 ufw，腾讯云安全组要单独放行 80/9099。
6. **腾讯云公网 IP 取** `metadata.tencentyun.com/latest/meta-data/public-ipv4` 最稳。

### 网关 / 网页端
7. **`--tls-cert/--tls-key` 必须要有 parseArgs 解析行**，否则传了被静默忽略、网关照走明文——「以为加密了其实没有」，最危险的一类 bug。
8. **upgrade 被拒绝的路径必须挂 `socket.on('error')`**：客户端立即退出时内核发 RST，无监听 → 未捕获 ECONNRESET → **整个网关退出**。一个人一个请求就能打断全部会话。
9. **`--redirect-port` 无条件 301 会封死 IP 入口**：把 `http://IP` 也跳到证书不含的 https，浏览器白屏。要用 `--tls-host` 只对证书域名跳转。
10. **RST 复现必须用独立子进程** `process.exit(0)`；in-process 读走数据再 destroy 只发 FIN，抓不到。
11. **`[hidden]` 打不过 `display:grid`** → 必须写 `[hidden]{display:none!important}`。
12. **ui-shot 复用同一 `--user-data-dir` 会挂到旧实例** → 每次用 `_profile-<pid>`。

### 协议
13. **群消息广播帧 `type` 是 `group`，不是 `msg`**；自己发自己不回显，测延迟必须两条连接。
14. **服务端 `pong` 帧不带 id** → 请求匹配要么按 id 要么按类型（`Request(..., expectType)`）。
15. **服务端 sessions 是单会话 Map**，每个命令各连一次会被「已在别处登录」踢 —— agentbus 因此拆成 daemon/watchdog/agentbus 三进程。

### 测试纪律
16. **任何压测/探活脚本都不能往线上可见数据里写东西** —— 曾把 `probe-*` 测试消息灌进 `#general`，只能停服改 JSON 才清干净。现在延迟脚本用互发私信，不写房间。

## 九、域名结论（重要，别再绕弯路）

**`nodechat.example.com` 是第三方公共子域服务（`is-gay-registration.pages.dev`）分出来的，不是自有域名。**

- zone 归服务方，NS 在 clouDNS（`pns5x.cloudns.net`），用户无法改 NS 委派
- 在自己 Cloudflare 账号添加 `example.com` 会**永远停在 Pending**（权限不在手）
- CF 免费版只能加二级域，`nodechat.example.com` 三级域属 Business 功能
- **且该域名已被机房按 SNI 拦截**：HTTP 302 到腾讯云封禁页，HTTPS 握手即 RST；`.gay` 不在工信部批复顶级域列表，无法备案

**结论：这台广州机器上域名+HTTPS 方案走不通，直接打 IP 最快。** 真要域名只能：换境外节点，或买自有二级域（.xyz 首年几块钱）后接 Cloudflare。

### Cloudflare 隧道（cloudflared）验证结论
- 链路通（机器主动出站 QUIC→CF 边缘），但落点固定 **洛杉矶**，`--region apac` 不存在，`--edge` 已移除，改不了
- 代价：延迟是直连的 **24 倍**（投递 337ms vs 14ms），交互发涩
- 且仍要求**自有可改 NS 的域名**才值得做
- 相关脚本 `web/deploy/enable-tunnel.sh` 已备好，`web/test/cf-latency.mjs` 可测

## 十、安全现状与遗留待办

### 安全现状（公开须知）
- 传输**默认明文**，未开 `--secure` 时密码以明文过网。桌面/安卓/C# CLI 目前只支持明文；Node 客户端与 agentbus 支持加密。
- 协议是「首次登录自动注册」，**公网任何人可注册**。要对外公开需改 `server/src/server.js` 的 `_handleAuth` 加白名单。
- 网页端没走应用层帧加密（网关不解析协议，做不了 `secure` 握手）。自用或小范围内部问题不大，对公网建议处理。
- 服务端指纹 `331df9c1:41fa757f:0aa4a8e0:1b4d1c85`（`identity.json` 决定，换文件即变）。

### 待办 / 未完成
1. **HTTPS 证书续期是手动的**（DNS-01），当前证书已停用（`certs.disabled-20261121`），2027-02-19 到期。域名不可用，**不建议续**，等有新域名再走。
2. **v1.0.1 不含 `web/`**，需要打 v1.0.2。
3. **桌面/安卓/C# CLI 仍是明文 TCP**；C# net48 无 `AesGcm`，需 AES-CBC + HMAC 替身才能加密。
4. **mentions 三段式**（服务端透传 → 发端 `--mention` → 收端判定）已设计未实现。
5. **公网开放即任何人可注册** —— 如需公开使用，务必先做白名单（见安全现状）。
6. `id_ed25519` 建议移出项目并回收。
